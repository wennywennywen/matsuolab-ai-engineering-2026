## 宿題

- 取り組んだレベル：基礎 
- 変えた設定やデータ：`num_train_epochs` を 20 → 5 に変更（40 ステップ → 10 ステップ）。ほかの設定は同じ。結果は `result_epoch5.json` / `eval_after_epoch5.json`
- 結果（比較表や数字）：

  | | 元の設定（20 エポック） | 変更後（5 エポック） |
  |---|---|---|
  | `format_rate` | 1.0（21/21） | 1.0（21/21） |
  | `content_rate` | 0.857（18/21） | 0.714（15/21） |
  | 最終 loss | 0.0138 | 1.577 |
  | 学習時間 | 231 秒 | 56 秒 |
  | 根拠ありの質問（15 問）の正解 | 15/15 | 13/15 |
  | 根拠なしの質問（6 問）で `needs_review: true` にできた数 | 3/6 | 5/6 |
  | 根拠なしの質問（6 問）の正解（語句も含む） | 3/6 | 2/6 |
  | セクション 6（4 問） | needs_review 2 / asserted 2 | needs_review 2 / asserted 2 |

  - 形式は 5 エポックでも 21/21 守れた。loss はまだ 1.577 と高く、元の設定でも 10 ステップ時点の loss は 1.560 だったので、形式は学習のかなり早い段階で身につくと分かった。
  - 5 エポックでは確認要求が増えた（根拠なし 3/6 → 5/6）が、文面が定まらず、「確認が必要」の語句が抜ける・質問文をそのまま返すなどの失敗が出た。
  - 20 エポックでは文面は正確になったが、似た FAQ 項目があると断定しやすくなった。1 回ずつの比較なので、傾向として捉える。
- ファインチューニングが向く場面・向かない場面についての考察：
  - 向く場面：出力の形式や文体をそろえたいとき。今回、学習データ 14 件・約 4 分（231 秒）の学習で、形式遵守率が 0.095 から 1.0 になった。5 エポック（56 秒）でも形式は 1.0 になったので、形式は少ない学習で身につく。JSON などの決まった形式で毎回答えさせる用途には効果が大きい。
  - 向かない場面：新しい知識を覚えさせたいときや、「分からないときは確認を求める」判断を確実にしたいとき。今回、根拠なしの質問の半分で、FAQ の別項目を当てて断定した。間違いでも形式は完璧なので、かえって正しそうに見えてしまう。知識は検索（第3回の用語集のような仕組み）で渡し、根拠がないときの扱いは評価データで確かめるほうが安全だと考える。
